# MI50 팬·냉각 설정 (ARCTIC S4028-15K + 3D 쉬라우드)

작성 2026-07-20. MI50(패시브 서버 카드)를 데스크톱 섀시에서 능동 공랭하기 위한 팬/쉬라우드/`fancontrol` 설정 계획 + 실행 런북. 배경과 기존 쿨링 관측(무냉각 크래시·전력 캡·온도 임계값)은 [translate-gpu-mi50.md §MI50 쿨링](translate-gpu-mi50.md#mi50-쿨링--능동-냉각-필수)에 있고, 여기서 반복하지 않는다.

> **상태 (2026-08-06):** 운영은 맨팬 1개, **`fancontrol`이 MI50 junction 온도로 `pwm4`를 제어한다.** 구성: SYS_FAN2 헤더, 커브 `MINTEMP 60 / MAXTEMP 80 / MINPWM 26(1,587rpm) / MAXPWM 74(4,983rpm)`, 부팅 영속은 `fancontrol.service` + `/etc/modprobe.d/nct6687.conf`([deploy/](../../../deploy/README.md)). **Task 1·2·4 완료**(결과 아래). **Task 3(2팬 vs 3팬 A/B)은 쉬라우드 장착 대기.** **Task 5(온도 알람)는 보류** — 유휴 복귀가 빠르고(10초에 수십 °C 하강 실측) 커브가 junction을 직접 보므로.
>
> **지속 부하는 맨팬으로 못 잡는다 (2026-08-06 실측).** 3분 연속 풀로드에서 junction이 50초 만에 96°C에 닿는다. 팬 상한 5,208rpm은 46초에 97°C, 7,075rpm은 50초에 96°C — **36% 빠른 팬이 1°C를 샀다.** **전력 캡도 답이 아니다** — 120W는 10초를 벌 뿐이고, 100W라야 135초로 늘지만(토큰 -11.2%) 그래도 3분을 못 버틴다(§전력 캡). 열이 나는 양이 아니라 **빼내는 양이 병목**이고 그 병목은 쉬라우드 없는 정압 누설이다 → Task 3. 운영은 150W를 유지한다. 실사용 패턴인 16~42초 버스트는 현재 커브로 여유가 있다(포화 P1/P2/P4·파이프라인 conc4 전부 완주, 피크 ≤89°C — [translate-gpu-mi50.md §신냉각 1차 실측](translate-gpu-mi50.md)).
>
> **평형점은 95°C 밖에 있다 (2026-08-10 실측).** 챕터를 연달아 돌리면 junction이 **0.57~0.59°C/s로 꺾이지 않고** 오른다 — 21페이지 챕터 1개는 80°C로 끝나지만 2개째에서 86°C에 닿고, 직선을 연장하면 95°C까지 약 40초다. **후반은 이미 팬이 MAXPWM에 붙은 뒤의 기울기**라 rpm 상향으로 살 수 있는 구간이 아니다(§연속 주행 실측). 실질 한계는 **연속 2챕터**이고, 13초 부하 뒤 원위치까지 30초 이상 걸린다.
>
> **열저항은 풍량을 끝까지 따라간다 (2026-08-12 실측).** 60W 캡으로 진짜 정상상태를 만들어 `R_th = (junction−31)/P`를 직접 읽으면 5,276→8,615rpm에서 **0.766 → 0.629 → 0.526 °C/W**, 세 점이 `R_th ∝ V^-0.77`에 맞는다(§60W 정상상태). 강제대류의 전형적인 지수이고 **검출 가능한 전도 바닥이 없다**(허용 상한 0.05 °C/W) — 풍량이든 결합이든 개선하면 계속 먹힌다는 뜻이다. 흡기는 31°C이고 팬 속도와 무관해 재흡입은 유의미하지 않다.
>
> **최고속 + 100W면 지속 부하가 성립한다 (2026-08-12 실측).** pwm 128(8,677rpm)에 100W 캡으로 연속 부하를 걸면 **junction 85.0°C에서 열평형**이다(mem 77°C, 천장까지 9°C). 이 카드에서 부하 중 곡선이 꺾인 첫 사례다 — 승온률이 0.057 → 0 으로 수렴하고 음수까지 오간다(§100W 지속 검증). 같은 100W가 운영 상한(MAXPWM 74, 약 5,000rpm)에서는 110°C이므로 **차이는 전부 팬 상한**이다. 필요한 변경은 `MAXPWM 74 → 128`과 지속 작업 시 `150W → 100W` 둘뿐이고, 대가는 토큰 −11.2%와 부하 중 소음이다. 150W 지속은 `R_th ≤ 0.36`이 필요해 32% 모자라고 멱함수를 연장하면 약 13,000rpm이라 소음 상한 밖이지만, **같은 rpm에서 그 32%를 얻는 수단이 쉬라우드**이므로 차단된 목표는 아니다.

## 미확정 — 이 작업으로 결정할 것

- **2팬 vs 3팬.** 분석상 2팬 우세(병렬 팬 이득 2~6%뿐, 2팬이 ~1.2 dB 조용, 허브 불필요). 단 카드 끝단 흡입 개구부 높이가 커서 2팬이 못 덮으면 3팬이 유리. **양쪽 쉬라우드 실물이 있으므로 추측 말고 Task 3의 실측 A/B로 결정.**

## 핵심 원칙 (설정 시 반드시 지킬 것)

1. **보드는 GPU 온도를 모른다.** SYS_FAN 헤더는 기본 CPU/보드 온도로 팬을 돌린다 → BIOS 팬커브로는 절대 해결 안 됨. 반드시 소프트웨어(`fancontrol`)로 `amdgpu` 온도에 매핑. (기존 관측: CPU 커브는 GPU 단독 부하를 못 추적해 junction 105°C까지 간 실측 있음 — [translate-gpu-mi50.md:38](translate-gpu-mi50.md#L38).)
2. **판단 기준 온도는 `junction`(temp2)과 `mem`(temp3).** `edge`(temp1)는 느긋해서 쓰지 말 것. Vega20/MI50은 **HBM2(mem)가 먼저 병목**되는 경우가 많으니 mem을 반드시 같이 감시.
3. **온도 상한:** junction ~95°C, **mem ~90°C 목표 상한**(mem 95°C가 실질 물리 한계, amdgpu crit=94°C). 스로틀은 junction ~100°C(crit) 부근.
4. **팬 고장은 tach로 감지 불가**(Y스플리터가 한쪽 tach만 리턴). **감시는 팬 rpm이 아니라 GPU 온도로 한다.**

## Task 1 — 센서 확인

- `sensors` 출력에서 `amdgpu` hwmon을 찾고, temp1/temp2/temp3이 각각 edge/junction/mem 중 무엇인지 매핑 확정 후 보고(라벨은 드라이버 버전마다 다를 수 있으니 추측 금지, 실제 출력으로 확인).
- 보드 팬 제어 칩(`nct6775` 등) hwmon과 `pwmX` 경로도 확인.
- 참고: 기존 관측상 `rocm-smi --showtemp`가 edge·junction·mem 셋 다 노출하고, amdgpu crit은 junction 100/emerg 105, mem crit 94/emerg 99 — Task 1은 hwmon `tempN` 라벨을 이 값에 대응시켜 최종 확정만 하면 됨.

**결과 (2026-07-26) — 완료.**

- **MI50** = PCI `0000:03:00.0`, amdgpu hwmon의 `temp1/2/3` 라벨 = **edge/junction/mem** (라벨 실측 확인).
- **보드 팬 칩 = NCT6687D**(MSI PRO B850M-A WIFI). EL10 커널엔 드라이버가 없어(`nct6683` 모듈 미탑재) [Fred78290/nct6687d](https://github.com/Fred78290/nct6687d)를 빌드해 `/lib/modules/$(uname -r)/extra/` + `modules-load.d`로 영구 로드했다. **Secure Boot는 무서명 모듈을 거부하므로 꺼야 한다**(BIOS에서 Disabled 처리됨). **커널 업데이트 시 재빌드 필요.**
- **ARCTIC 팬 채널 = `nct6687` hwmon의 ch4**(라벨 "System Fan #2"). 수동 제어: `pwm4_enable`에 1 → `pwm4`에 0~255.
- **EC 특성:**
  - **`msi_fan_brute_force=1`이 필수다.** 없으면 EC가 `pwm4`에 쓴 값을 1초 안에 자기 커브 값으로 되돌리고(readback이 목표와 다름), **duty 바닥이 강제**돼 pwm 0에도 ~4,360rpm 아래로 안 내려간다. 켜면 커브 7포인트를 전부 써서 EC를 밀어내므로 쓴 값이 그대로 유지되고 바닥도 사라진다(pwm 0 = 1,046rpm). `/etc/modprobe.d/nct6687.conf`에 고정한다 — dmesg의 `MSI fan brute force mode: enabled`로 확인.
  - 값을 **내리는 방향은 EC가 수 초~수십 초에 걸쳐 수렴**시킨다(올리는 방향은 즉시). `fancontrol`은 `INTERVAL`마다 다시 쓰므로 결국 수렴한다.
  - **자동 모드(`pwm4_enable=2`)는 CPU 온도 커브다.** MI50이 49°C로 놀아도 CPU가 48→75°C로 오르면 팬이 3,846→7,042rpm까지 따라 올라가고, 반대로 CPU가 놀고 MI50만 뜨거우면 팬이 안 올라간다 — §핵심 원칙 1의 실증이다.

## Task 2 — PWM↔rpm 매핑 측정 (새 ARCTIC 팬 장착 후)

- 팬이 물린 `pwmX`에 값을 직접 write(수동 제어 활성화)하며 실제 rpm 측정, 표 작성:
  - PWM 듀티 **20/30/40/50/60/70/80/100%** → 실측 rpm
- 목적: `fancontrol` 커브의 MINPWM/MAXPWM을 실측으로 넣기 위함. 특히 **8,500 rpm에 해당하는 PWM 듀티값**을 정확히 확보(MAXPWM 캡에 사용).

**결과 (2026-08-06) — 완료** (맨팬 1개, `msi_fan_brute_force=1`, `pwm4_enable=1`):

| pwm | 0 | 26 | 51 | 77 | 102 | 128 |
|---|---|---|---|---|---|---|
| rpm | 1,046 | 1,587 | 3,432 | 5,154 | 7,075 | 8,823 |

- **소음 체감**: 5,000rpm부터 들리기 시작하고 6,400rpm이면 꽤 시끄럽다. 7,075rpm은 GPU 부하 중에만 나온다면 감수 가능한 수준.
- **MINPWM 하한은 26**(1,587rpm)으로 잡는다 — pwm 0의 1,046rpm은 팬 정격(1,400~15,000rpm) 밖이라 회전이 불안정할 수 있다.
- 쉬라우드 장착 후에는 정압이 달라지므로 이 표를 다시 뜬다.

## Task 3 — 쉬라우드 A/B 온도 비교 ★ (쉬라우드 도착 후에만)

- **쉬라우드가 없으면 이 Task 건너뛰고 "쉬라우드 대기 중" 명시 보고.** 맨 팬 상태의 **절대 온도**는 정압 누설로 무의미하므로 측정하지 않는다. 단 **열저항 특성화는 예외**다 — 맨팬 상태에서도 전도 항과 대류 항이 갈라지고, 그게 쉬라우드가 넘을 수 없는 상한을 알려준다(§팬 속도별 열저항).
- **절차** — 정상상태 로깅은 쓸 수 없다. 평형이 안전 범위 밖이라 "정상상태까지 대기 후 10분 로깅"은 가드에 잘려 첫 분도 못 채운다. 대신 [bench_cooling_ab.py](bench_cooling_ab.py)로 **결합도**를 구성마다 잰다:
  1. `--label shroud2 --sweep 26,77,102,128` — 구성마다 같은 듀티 집합, 같은 부하(P=4), 같은 게이트(70→80°C).
  2. 쉬라우드 교체 후 `--label shroud3`로 동일 반복. 팬 개수가 바뀌면 듀티↔rpm이 달라지므로 **비교 축은 duty가 아니라 실측 rpm**이다.
  3. `--compare cooling_shroud2.json cooling_shroud3.json`으로 나란히 본다.
  4. 각 구성의 R_th를 `R_전도 + k·V^-0.65`로 분해해 **대류항이 얼마나 줄었는지**를 본다. 전도항(≈0.35)은 쉬라우드로 안 변하는 게 정상이며, 변했다면 측정이 틀린 것이다.
- **측정 전 육안 확인:** 3팬 쉬라우드에 팬 3개 다 꽂혔는지 / 2팬 쉬라우드에 빈 개구부 누설 없는지. 뚫려 있으면 그 데이터는 신뢰하지 말 것. 2팬(80mm)이 카드 끝단 흡입 개구부를 상하단까지 다 덮는지 관찰.
- **목표치.** 흡기 31°C 기준으로 지속 부하가 85°C를 넘지 않으려면 `R_th ≤ (85−31)/P`다 — **150W면 0.36**, **120W면 0.45**, **100W면 0.54**. 맨팬 최고속(8,615rpm)이 이미 0.526이므로 100W는 쉬라우드 없이 통과한다. 따라서 **쉬라우드의 합격선은 같은 rpm에서 0.45(120W) 이하**로 잡고, 0.36에 닿으면 150W 지속이 열린다. 검출 가능한 전도 바닥이 없으므로(§60W 정상상태) 이 목표들은 물리적으로 차단돼 있지 않다.
- **판정은 60W 정상상태로 한다.** `--steady --steady-watts 60`이 모형을 거치지 않고 R_th를 직접 준다. 위 결합도 스윕은 보조로만 쓴다.
- **판정 로직:**
  - **둘 다 junction ≤ 95 && mem ≤ 90** → **2팬 채택**(더 조용·배선 단순), 3팬은 여분.
  - **2팬만 초과, 3팬은 통과** → 개구부를 2팬이 못 덮는 것. **3팬 채택.**
  - **둘 다 초과** → 소음 상한으로 rpm을 더 못 올림 = 팬으로 답 없음. **파워캡 150→120W로 내리고 재측정** 제안. 팬 개수로 해결 시도하지 말 것.
  - **mem만 튀고 junction은 여유**(구성 무관) → 쉬라우드 상하단 데드존 의심. 해당 쉬라우드 재출력(팬 커버리지 조정) 검토를 보고.
- **채택 구성을 명확히 보고**하고, Task 4는 그 구성 기준으로 진행.

## 전력 캡 — 지속 부하 완화 실측 (2026-08-06)

위 판정 로직의 "팬으로 답 없음 → 파워캡" 경로를 실제로 돌린 결과다. 같은 3분 풀로드(4 동시요청), junction 96°C 도달까지의 시간과 토큰 속도:

| 캡 | 토큰 속도 | 96°C 도달 | 시작 junction |
|---|--:|--:|--:|
| 225W (vBIOS 기본) | 91.2 t/s (+0.5%) | — (측정 안 함) | 58°C |
| **150W (운영)** | 90.7 t/s | 50초 | 49°C |
| 120W | 86.3 t/s (−4.8%) | 60초 | 60°C |
| 100W | 80.5 t/s (−11.2%) | **135초** | 54°C |

- **150W가 무릎이다.** 캡을 완전히 풀어도 +0.5%뿐이고 아래로는 바로 손실이 시작된다. decode가 메모리 대역폭에 묶여 있어(89.3 t/s = 대역폭 피크의 19%, [translate-gpu-mi50.md](translate-gpu-mi50.md)) 전력을 더 줘도 쓰지 못한다 — **전력 캡은 성능 레버가 아니라 발열 레버다.**
- **225W에서는 512토큰 한 번(약 6초)에 junction이 58 → 80°C로 오른다.** 지속 부하가 임계에 닿는 속도가 여기서 설명된다.
- **120W는 사실상 무의미하다** — 전력을 20% 깎고 10초를 번다. 문서가 처음 지목했던 값이지만 실측이 기각한다.
- **100W가 변곡점**이다(2.7배). 대신 토큰이 11% 깎이고, **그래도 3분을 못 버틴다.**
- 어느 캡에서도 지속 부하는 결국 임계에 닿는다. **완화이지 해결이 아니므로 운영은 150W를 유지**하고, 지속 부하를 실제로 돌리게 되면 쉬라우드(Task 3)를 먼저 한다.
- **MI50에는 온도 스로틀이 없다.** 섀시가 강제 냉각을 책임지는 전제로 만든 카드라, 한계에 닿아도 클럭을 낮추며 버티는 완충이 없고 온도가 그대로 계속 오른다(기존 junction 105°C 실측이 그 결과다). 지속 부하를 돌릴 거면 **Task 5(온도 가드)가 캡보다 먼저**다.

## 열 평형은 95°C 밖에 있다 — 연속 주행 실측 (2026-08-10)

앞의 두 절이 "지속 부하는 결국 임계에 닿는다"를 시간으로 보였다면, 이 절은 **왜 닿는지**를 보인다. 21페이지 챕터를 간격 없이 연달아 돌리며(P=4, 150W, 팬 설정 미변경) 0.5초 간격으로 센서를 로깅했다. 측정은 [bench_translate_sustained.py](bench_translate_sustained.py) — 요청 body는 [bench_translate_concurrency.py](bench_translate_concurrency.py)를 재사용하므로 플러그인이 보내는 것과 같은 배치다.

| 챕터 | 시간 | junction | mem | 팬 |
|---|--:|--:|--:|--:|
| 1 (21/21) | 13.2s | 54 → **80°C** | 67°C | 1,583 → 4,360 rpm |
| 2 (19/21, 컷) | 11.3s | 79 → **86°C** | 71°C | 5,154 rpm (MAXPWM) |

- **곡선이 안 꺾인다.** 계단 응답이 끝난 뒤 기울기는 **74→80°C 구간 0.59°C/s, 80→86°C 구간 0.57°C/s**로 같다. 평형에 접근하면 완만해져야 하는데 그 조짐이 없다 — 이 부하에서 **평형점은 95°C 밖에 있다.** 직선을 연장하면 95°C까지 약 40초로, §전력 캡의 "49°C 시작 50초에 96°C"와 맞는다.
- **후반 곡선은 이미 최대 풍량에서의 곡선이다.** 팬은 14.6초에 MAXPWM 74에 붙었고 그 뒤로도 기울기가 같았다. 팬이 1,583 → 5,154 rpm으로 3배 넘게 오르는 동안 기울기는 3% 변했다. §상태의 "36% 빠른 팬이 1°C"를 다른 방법으로 재확인한 것이고, **rpm 상향이 남은 카드가 아니라는 뜻**이다. 남은 물리 레버는 Task 3뿐이다.
- **실질 한계는 챕터 2개**다. 1개(13초)는 80°C로 끝나지만 2개째에서 컷에 닿는다. 챕터 1개가 §상태의 버스트 여유(피크 ≤89°C)보다 높게 나온 것은 시작 온도 차이다(54°C 시작).
- **유휴 복귀는 앞이 빠르고 뒤가 느리다.** 86°C에서 부하를 끊으면 즉시 71°C로 떨어지지만 이후 30초 동안 64 → 63 → 62°C로 완만해진다. 13초 돌리면 30초 이상 쉬어야 원위치다. 이 비대칭 때문에 **연속 사용에서는 Task 5가 필요해진다** — 버스트만 도는 동안 급하지 않다는 판단은 챕터 사이에 실제로 유휴가 있을 때만 성립한다.

**센서 이상값은 power로 판별된다.** 핵심 원칙 2가 경고한 튐(연속 읽기 사이 10~20°C)이 그대로 나왔는데, 낮게 튄 표본은 **예외 없이 power도 ~23W로 함께 떨어진다**(부하 중 정상값은 130~170W). hwmon 블록이 유휴 시점 값을 반환하는 것으로 보인다. 온도만 보면 노이즈지만 power를 같이 읽으면 걸러낼 수 있으니, 가드를 짤 때 **부하 중 power가 비정상적으로 낮은 표본은 버린다**. 히스테리시스만으로 버티는 것보다 정확하다.

**측정 자체는 카드에 무해했다.** 최대 86°C(crit 100·ceiling 95 대비 여유 9°C)에서 멈췄고, 컷은 llama-server에 신호를 보내지 않고 요청 제출만 멈춘다(§[translate-gpu-mi50.md](translate-gpu-mi50.md)의 GPU 작업 중 kill 금지). 직후 건강 확인: dmesg에 MI50 관련 에러 0건, 유닛 무재시작, VRAM·PCIe(16 GT/s x16) 정상, **단일 스트림 디코드 90.3 t/s** — latch 판독 기준(식은 카드 ~90)에 부합한다.

## 팬 속도별 열저항 — 결합도 실측 (2026-08-12)

앞 두 절이 "지속 부하는 결국 임계에 닿는다"를 시간으로, "곡선이 안 꺾인다"를 기울기로 보였다면, 이 절은 **얼마나 모자란지**를 열저항으로 잰다. 측정은 [bench_cooling_ab.py](bench_cooling_ab.py) `--sweep`이고, 부하는 앞 절과 같은 배치다(P=4, 150W, 프로덕션 유닛).

**정상상태를 못 재므로 결합도를 잰다.** 평형이 안전 범위 밖이라 "정상상태까지 대기 후 로깅"이 성립하지 않는다(Task 3의 원래 절차가 이래서 실행 불가능하다). 대신 두 과도값을 쓴다 — 고정 rpm·고정 부하에서 junction 70→80°C **승온 기울기**, 그리고 부하 정지 후 냉각 곡선의 **시상수 τ**. 둘을 집중정수 모형 `C·dT/dt = P − (T−T_amb)/R_th`, `R_th = τ/C`에 넣으면 열저항이 나온다. 게이트가 80°C라 천장까지 15°C를 남기고 1회 1분 안에 끝난다.

| pwm | rpm | 기울기 | 전력 | τ | R_th | 유휴 junction |
|--:|--:|--:|--:|--:|--:|--:|
| 26 | 1,640 | 0.59 C/s | 155W | 259s | 1.129 | 55°C |
| 77 | 5,262 | 0.47 C/s | 149W | 183s | 0.781 | 49°C |
| 102 | 6,962 | 0.34 C/s | 147W | 178s | 0.643 | 44°C |
| 128 | 8,705 | 0.26 C/s | 142W | 184s | 0.585 | 42°C |

**흡기는 31°C다.** 보드에 흡기 센서가 없다. 냉각 곡선 피팅이 내놓는 점근선은 창이 3τ에 못 미치면 높게 치우치므로(아래 방법론) 쓰지 않고, 유휴 평형에서 역산한다 — `intake = junction − 20W × R_th`가 네 단계에서 32/33/31/30°C로 모인다. **팬 속도와 무관하다는 점이 중요하다**: 재흡입이 지배적이라면 풍량이 늘수록 흡기가 시원해져야 하는데 그렇지 않으므로, 자기 배기를 다시 먹는 문제는 유의미하지 않다.

| pwm | rpm | R_th | Q@80°C | 150W 평형 | 100W 평형 | 85°C 유지 전력 |
|--:|--:|--:|--:|--:|--:|--:|
| 26 | 1,640 | 1.129 | 43W | 200°C | 144°C | 48W |
| 77 | 5,262 | 0.781 | 63W | 148°C | 109°C | 69W |
| 102 | 6,962 | 0.643 | 76W | 127°C | 95°C | 84W |
| 128 | 8,705 | 0.585 | 84W | 119°C | 90°C | 92W |

`Q@80°C = (80−31)/R_th`는 junction 80°C에서 실제로 빠져나가는 와트다. **어느 rpm에서도 150W에 못 미친다(43~84W)** — 차액이 매번 쇳덩이를 데우므로 온도는 Q가 150W가 될 때까지 오른다. 평형 온도는 선형 외삽이지 도달하는 값이 아니고(실제 대류·복사는 ΔT가 커지면 강해진다), "안전 범위 안에 평형점이 없다"를 정량화한 값으로 읽는다.

**이 표의 τ와 R_th는 서로 어긋난다.** τ는 178 → 184초로 102와 128이 사실상 같은데 R_th는 0.643 → 0.585로 128이 낮다. `R_th = τ/C`인데 C를 승온 기울기에서 따로 추정하기 때문이고, 역산한 C가 상수여야 함에도 204 → 285 J/°C로 단조 증가한다. 아래 §60W 정상상태가 이 불일치를 직접 측정으로 갈랐고, **이긴 쪽은 R_th다** — τ 쪽이 노이즈였다(창이 1.9τ뿐이라 178과 184는 구분되지 않는 값이다). **모형 R_th는 pwm 77·102에서 실측과 2% 이내로 맞았고, 128에서만 10% 보수적이었다.**

그 밖에: 단계당 1회 측정이다. pwm 26 행은 τ가 259초여서 창이 1.35τ뿐이라 신뢰도가 가장 낮다 — **이 행을 회귀의 지렛대로 쓰지 말 것.** 이 표만으로 전도·대류 분해를 시도하면 pwm 26에 끌려가 전도 바닥이 크게 나오는데, 직접 측정은 그런 바닥을 보여주지 않는다(§60W 정상상태).

## 60W 정상상태 — 모형 없이 읽은 열저항 (2026-08-12)

위 표의 R_th는 `τ/C`라는 모형을 거친 값이고 C가 상수로 나오지 않았다. 전력 캡을 낮추면 **평형이 안전 범위 안으로 들어오므로** 모형이 통째로 필요 없어진다 — 부하를 걸어둔 채 junction이 멈출 때까지 기다렸다가 `R_th = (junction − 31) / P`를 읽으면 된다. 측정은 [bench_cooling_ab.py](bench_cooling_ab.py) `--steady --steady-watts 60`이고, 캡은 `finally`와 시그널 양쪽에서 복원한다.

| pwm | rpm | 평형 junction | mem | 전력 | **R_th(실측)** | 모형값 | 차이 |
|--:|--:|--:|--:|--:|--:|--:|--:|
| 77 | 5,276 | 78.6°C | 73°C | 62.1W | **0.766** | 0.781 | −2% |
| 102 | 6,921 | 70.4°C | 66°C | 62.6W | **0.629** | 0.643 | −2% |
| 128 | 8,615 | 63.6°C | 60°C | 62.1W | **0.526** | 0.585 | −10% |

**흡기 31°C가 검증됐다.** 세 점이 −2%/−2%/−10%로 계통적으로 조금씩 낮으니 실제 흡기는 30°C에 더 가깝다. 유휴 평형에서 역산한 값이 독립적인 방법으로 재확인된 셈이다.

**전도 바닥은 검출되지 않는다.** 세 점을 로그-로그로 맞추면 **`R_th ∝ V^-0.77`**이고, 이는 강제대류의 전형적 지수(0.6~0.8) 한가운데다. 고정 전도항을 0.15로 놓으면 대류 지수가 1.0이어야 하는데 물리적으로 불가능하므로, **데이터가 허용하는 전도 바닥은 0.05 °C/W 이하**다. 전도항이 물리적으로 0일 수는 없으니 "이 rpm 구간에서 검출되지 않을 만큼 작다"로 읽는다. **풍량이든 결합이든 개선하면 계속 먹힌다.**

**지속 부하에 필요한 R_th** (흡기 31°C, junction 85°C 기준 `R_th ≤ (85−31)/P`):

| 전력 | 필요 R_th | 현재 최고속(0.526)으로 | 운영 상한 ~5,000rpm(0.79)으로 |
|--:|--:|---|---|
| 100W | 0.54 | **가능** (평형 84°C) | 불가 (110°C) |
| 120W | 0.45 | 14% 부족 | 불가 |
| 150W | 0.36 | 32% 부족 | 불가 |

**최고속 팬 + 100W 캡이면 쉬라우드 없이도 지속 부하가 성립한다.** 같은 100W가 운영 상한에서 불가능한 것은 순전히 팬 상한 차이다. 150W는 32%가 모자라고 멱함수를 연장하면 약 13,000rpm이 필요해 소음 상한 밖이지만, **같은 rpm에서 그 32%를 얻는 수단이 쉬라우드**이므로 차단된 목표는 아니다.

**유보.** 세 점뿐이고 rpm 범위가 1.63배로 좁아 지수 0.77이 단단하지 않다. pwm 102는 100초 만에 평형 판정됐는데 τ가 180초대인 것을 감안하면 조기 종료가 의심된다(그렇다면 진짜 값은 더 높고, 지수는 더 커져 결론은 같은 방향이다). 판정 기준에 최소 유지 시간(`--steady-min-s`, 기본 400초)을 넣은 것은 이 때문이다.

## 100W 지속 검증 — 평형이 실제로 잡힌다 (2026-08-12)

위 절이 "100W면 R_th가 충분하다"를 계산으로 보였다면, 이 절은 그걸 그대로 돌려서 확인한다. 팬을 pwm 128에 고정하고 캡을 100W로 내린 뒤 연속 부하를 걸었다. 컷은 평형 예측(85°C)이 기본 컷과 겹치므로 `--cut 90 --cut-hard 92 --cut-project 93 --cut-mem 85`로 올렸다 — **평형 근처에서는 승온률이 0이라 오버슈트 위험이 전속력 상승 때와 다르다**는 것이 근거다.

```
pwm 128 (8,677 rpm) · 100W 캡 · P=4 · 600초에 평형 판정
  junction 85.0°C @ 97.4W · mem 77.1°C · R_th 0.555 C/W
  관측 최고 86°C (천장 95°C, 여유 9°C)
```

**승온률이 0으로 수렴하고 음수까지 오간다** — 0.057 → 0.041 → 0.028 → 0.013 → 0.002 → −0.003. §연속 주행 실측에서 0.57~0.59°C/s가 두 구간 내내 3%밖에 안 변하며 끝까지 직선이었던 것과 대비된다. 이 카드에서 부하 중 곡선이 꺾인 첫 사례다.

**R_th가 전력에 약하게 의존한다.** 60W에서 0.526, 100W에서 0.555로 5.5% 높다. 전력이 커지면 케이스 안 공기가 더 데워져 실효 흡기가 오르는 것으로 보인다. 작지만 실재하는 항이므로 **더 높은 전력으로 외삽할 때는 이만큼 보수적으로 잡는다.**

**유보.** 10분 한 판이다. 마지막 100초가 기울기 0이었으나 "무한히"는 여전히 외삽이고, 30~60분을 돌리면 케이스가 서서히 데워지며 몇 °C 더 오를 여지가 있다. 그리고 85°C는 천장에서 10°C뿐이므로 **Task 5(온도 가드)는 계속 필요하다** — 이유가 "평형이 없어서"에서 "여유가 10°C뿐이라서"로 바뀌었을 뿐이다.

**운영에 반영하려면** `/etc/fancontrol`의 `MAXPWM`을 74에서 128로 올리고([deploy/fancontrol.example](../../../deploy/fancontrol.example)도 함께), 지속 작업 동안 캡을 100W로 내린다. 버스트만 도는 평소에는 현재 커브가 이미 여유가 있으므로(피크 ≤89°C) 바꿀 이유가 없다 — **상시 8,600rpm은 소음 대가가 크다.**

**방법론 — 같은 함정을 다시 밟지 않도록.**

- **냉각 피팅 창은 최소 3τ.** 처음엔 120초로 돌렸고 τ가 114초로 나왔는데, 350초로 늘리자 같은 조건에서 259초가 됐다. 1τ만 보고 지수함수를 맞추면 τ와 점근선이 서로를 흡수해 **둘 다 낙관 쪽으로 틀린다.** 창이 짧으면 흡기 추정이 유휴 junction보다 높게 나오는 물리적 불가능이 발생하니, 그 값이 나오면 창을 의심한다.
- **부하 정지 직후 10~15초는 버린다.** junction이 3초 만에 15°C 떨어지는 구간은 다이↔싱크 온도차가 붕괴하는 것이지 열이 빠지는 게 아니다. 그 구간을 피팅하면 싱크가 아니라 다이의 시상수가 나온다.
- **소킹 기준은 τ에 맞춘다.** "0.05°C/s가 20초간 평평"은 τ가 259초일 때 평형까지 13°C를 남기고도 통과한다. 창을 3τ로 늘리면 냉각 시간 자체가 소킹을 겸한다.
- **투영 가드의 무장 온도는 게이트 위에 둔다.** [bench_translate_sustained.py](bench_translate_sustained.py)의 78°C를 그대로 쓰면 80°C 게이트에 접근하는 것만으로 컷이 걸린다. 계속 오를 작정인 도구와 게이트에서 멈출 작정인 도구는 무장 지점이 달라야 한다.
- **`fancontrol`을 멈추면 EC가 즉시 채널을 되찾는다.** duty를 한 번만 쓰면 1초 안에 CPU 커브 값으로 밀려난다(첫 시도에서 pwm 26을 쓰고 5,617rpm이 나왔다). 1초 주기로 다시 쓰는 홀더가 필요하고, 측정 구간의 **실측 평균 rpm을 기록**해야 홀더가 졌을 때 데이터에 드러난다. 임시 `/etc/fancontrol`로 고정하는 방법은 쓰지 않는다 — 죽으면 잘못된 커브가 디스크에 남아 재부팅을 넘어 살아남는다.

## Task 4 — fancontrol 영구 설정 (채택 구성 기준)

- `lm-sensors`, `fancontrol` 설치 → `sensors-detect` → `pwmconfig`.
- **`/etc/fancontrol` 수동 편집**하여 `FCTEMPS`를 `amdgpu` junction(temp2)에 매핑. `pwmconfig` 자동 생성값(보드 센서만 제안)을 그대로 쓰지 말 것.
- 커브 값은 Task 2/3 실측 기반. **MAXPWM을 8,500 rpm 듀티로 캡**(15,000 rpm/100%로 두지 말 것 — 소음 상한). MAXTEMP는 junction ~85 부근.
- **hwmon 번호는 재부팅마다 변동.** `fancontrol`이 생성하는 `DEVPATH`/`DEVNAME` 라인 유지(불일치 시 서비스 시작 거부 → 조용한 오작동보다 안전).
- `systemctl enable --now fancontrol` 후 **재부팅 테스트까지** 확인.

**결과 (2026-08-06) — 완료** (맨팬 기준. 쉬라우드 장착 시 Task 2/3 재측정 후 커브를 다시 잡는다). `/etc/fancontrol` 핵심:

```
FCTEMPS=hwmon6/pwm4=hwmon1/temp2_input     # MI50 junction
INTERVAL=5
MINTEMP=60   MAXTEMP=80
MINPWM=26    MAXPWM=74
MINSTART=40  MINSTOP=26
```

| junction | ≤60°C | 65°C | 70°C | 75°C | ≥80°C |
|---|---|---|---|---|---|
| rpm | 1,587 | ~2,700 | ~3,700 | ~4,300 | 4,983 |

- **`MINTEMP 60`** — 유휴·경부하를 1,587rpm에 평탄하게 눕히려는 것이다. 소음이 들리기 시작하는 5,000rpm 구간을 junction 80°C 위로 밀어냈다.
- **`MAXPWM 74`(~4,983rpm)는 청취 기준으로 고른 값이지 냉각 여유로 고른 값이 아니다.** 상한을 7,075rpm까지 올려도 지속 부하 온도가 1°C밖에 안 내려가므로(§상태) 소음만 손해다.
- **`MI50-fan-duty.service`는 이 설정이 대체하므로 제거했다.** oneshot 고정 duty는 EC가 되찾아가 CPU 온도를 따라 진동했고, GPU 온도를 아예 보지 못했다.
- hwmon 번호는 부팅마다 바뀌므로 `DEVPATH`/`DEVNAME` 줄을 유지한다.

**부팅 함정 — `nct6687`은 `modules-load.d`로 못 올린다 (2026-08-06 실측).** 부팅 초기엔 Super I/O EC가 응답하지 않아 모듈이 `EC base I/O port unconfigured` → `Failed to insert module 'nct6687': No such device`로 죽는다. 같은 `modprobe`가 수십 초 뒤엔 성공하므로 **경합이 아니라 재시도로 풀어야 한다** — [`nct6687-load.service`](../../../deploy/nct6687-load.service.example)가 2초 간격 15회 재시도하고, `fancontrol`은 drop-in으로 이 유닛을 `Requires=`/`After=`에 건다. 이게 없으면 `fancontrol`이 `Device path of hwmonN has changed`로 종료하고 **팬이 조용히 EC 커브(CPU 온도)로 되돌아간다** — 재부팅 직후 MI50이 48°C인데 CPU 72°C를 따라 7,075rpm으로 돌던 상태가 그것이다.

## Task 5 — 온도 알람 (하드웨어 무관, 지금도 배포 가능)

- junction 95°C 또는 mem 90°C 초과 시 경고하는 감시 스크립트/서비스 작성(로그 또는 알림). **rpm이 아니라 온도 감시.**
- **스로틀이 없는 카드라 이건 선택이 아니다.** 지속 부하에서는 어떤 팬 설정·전력 캡으로도 임계에 닿고(§전력 캡), 하드웨어가 스스로 클럭을 낮춰 버티지도 않는다. 온도를 보고 요청을 막거나 캡을 낮추는 층이 유일한 실질 방어다. 유휴 복귀가 빠른 버스트 부하만 도는 동안에는 급하지 않다.

## 다장착(2~3카드) 시 추가

- 채택된 쉬라우드 구성을 카드마다 동일 적용. 카드마다 헤더+스플리터 분리 → `fancontrol`에서 **카드별 junction을 카드별 pwm에 독립 매핑**. 가장 뜨거운 카드(보통 가운데)만 더 돌리는 구성이 목표.
- 카드가 여러 개면 `amdgpu` hwmon도 여러 개. Task 1에서 **카드↔hwmon 대응을 PCI 주소 기준**으로 명확히 해둘 것.

## 하지 말 것

- 맨 팬 상태의 **절대 온도**로 냉각 성능을 판정하지 말 것(정압 누설로 무의미). 열저항 특성화는 예외(§팬 속도별 열저항).
- **τ와 `R_th = τ/C`가 어긋날 때 τ를 믿지 말 것.** 창이 3τ에 못 미치면 τ는 직접 피팅한 값이어도 단단하지 않다 — 실측이 R_th 편을 들었다(§60W 정상상태).
- **신뢰도 낮다고 표시한 점을 회귀의 지렛대로 쓰지 말 것.** pwm 26 한 점이 전도 바닥을 0.35로 만들었고, 직접 측정은 0.05 이하를 가리켰다.
- MAXPWM을 100%/15,000 rpm으로 두지 말 것(소음 상한 위반).
- `edge` 온도 기준으로 커브 짜지 말 것.
- BIOS 팬커브에 의존하지 말 것.
- 팬 브랜드·정압 재검토 금지(닫힌 결정). **단 2 vs 3팬은 Task 3 실측으로 결정하는 열린 항목**이므로 임의로 하나를 전제하지 말 것.
